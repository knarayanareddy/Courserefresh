# Courserefresh — static review

## Scope and verdict

**Stage:** implemented hackathon prototype, with a Python engine and two separate frontend packages. **Pinned revision:** `b475254cf7aafa5fb535a9987a48e5379ce57e27` on `main`. This is a scoped static review, not a production-readiness assessment. The recommended network demo exposes controls without authentication when tokens are unset, and the learning gate's reported window does not filter telemetry by age. A safe live rollout requires correction and observed verification.

Runtime, builds, installations, tests, external integrations and deployment were **NOT RUN**, by instruction. The README's 295-check claim is an author claim, not an observed result. The [remediation plan](REMEDIATION_PLAN.md) is proposed work only.

## Findings ledger

**CR-01 — High, confirmed static, high confidence: network control endpoints fail open without tokens.** [console.py:111–118](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L111-L118) returns `not self.token or ...`; [console.py:190–208](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L190-L208) gates pause/resume using it, while [console.py:328–337](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L328-L337) binds `0.0.0.0` and acknowledges writes “are open”. This contradicts the helper's loopback description. A reachable peer can pause or resume and may submit author rulings when no token is configured; the ruling handler checks the same authorization ([console.py:231–261](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L231-L261)) and appends the ruling and receipt after validation ([console.py:300–315](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L300-L315)). Console GET routes expose receipts and run logs without authentication even with a token ([console.py:144–156](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L144-L156)). Require authenticated, authorized access to both read and write routes; default to loopback and explicitly gate network exposure. Actual exposure depends on deployment.

**CR-02 — High, confirmed static, high confidence: telemetry's declared window and version are not enforced by the live revert path.** [telemetry.py:172–192](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/telemetry.py#L172-L192) sets and reports `window_h` without comparing timestamps. Its predicate `version is None or r.get("version") in (None, version)` accepts all versions when the argument is omitted and accepts unversioned rows even when it is supplied. [run_live.py:745–759](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/run_live.py#L745-L759) calls `cohort_window` without a version and feeds the result to the revert decision. Old or other-version data can affect cohort size and quiz delta, potentially causing or suppressing a revert. Define event-time boundaries, invalid/future timestamp behavior and owner-approved version eligibility, then wire and test these rules through the live learn-to-revert path with an injected clock.

**CR-03 — High, confirmed static, high confidence: shared/optional telemetry token does not bind a learner identity.** [telemetry.py:48–60](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/telemetry.py#L48-L60) checks only a `learner:<8 hex>` shape and client-supplied `consent`; [telemetry.py:223–244](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/telemetry.py#L223-L244) accepts or revokes consent for that handle and only checks a shared token if configured. The service binds all interfaces ([telemetry.py:269–279](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/telemetry.py#L269-L279)). A caller who knows a handle can submit or revoke on its behalf; an eight-hex pseudonym is not proof of identity. Live learner rollout needs authenticated identity binding, protected consent operations and abuse limits; actual exploitation was not tested.

**CR-04 — Medium, confirmed static, high confidence: presentation implies chain verification without performing it.** [AuthorConsole.tsx:42–52](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/viz/src/components/AuthorConsole.tsx#L42-L52) defines `chainOk` as `receipts[0].runId === register.heroRun`, but [AuthorConsole.tsx:69–78](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/viz/src/components/AuthorConsole.tsx#L69-L78) displays `chain ✓ ok` regardless of that boolean. The color changes, but equality of IDs is not a hash-chain check. A viewer can mistake a simulated label for verification; show a validated result with provenance or explicitly mark it unverified.

**CR-05 — Medium, confirmed static, high confidence: revert test accepts partial restoration.** [test_artifacts.py:73–83](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/tests/test_artifacts.py#L73-L83) passes if `any(line in revert_body.read_text()` for three distinctive lines plus a marker. A corrupt revert preserving one line can satisfy this check. Compare the complete expected restored content, with any intentional marker handled explicitly, and use a deliberately damaged artifact as a negative control. This is a test weakness, not proof that actual revert writing is defective.

**CR-06 — Medium, confirmed static, high confidence: delivery automation covers the visualization build only.** The complete captured tree lists one workflow; [deploy-viz-pages.yml:22–35](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/.github/workflows/deploy-viz-pages.yml#L22-L35) runs `npm ci` and `npm run build` in `viz`, then publishes `viz/dist`. It does not run the Python battery or build the separate video app. Its action references use mutable version tags. A Pages build cannot serve as a gate for engine behavior or dependency integrity. Add separate least-privilege PR checks and reviewed immutable action pins; do not interpret this as proof branch protection is absent.

**CR-07 — Low, confirmed static, high confidence: check counts conflict.** The [README:34–37](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/README.md#L34-L37) claims “295 checks”; [viz App.tsx:168–178](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/viz/src/App.tsx#L168-L178) presents “274” as “checks green”. Neither is independently measured here. Generate display values from a timestamped, revision-bound result or label them historical.

## Five-discipline assessment

1. **Correctness:** CR-02 and CR-05 affect measurement/revert. The sim provider and n8n parity comparison are positive design evidence, not runtime proof.
2. **Automation/testing:** CR-05–07; tests were not run. A Pages deployment succeeded at [efff96eaed9d49f023b3534a787ac0c7d77df19e](https://github.com/knarayanareddy/Courserefresh/actions/runs/36323706861), not the pinned revision; it proves neither current build nor engine behavior. Two other collected runs also succeeded at different SHAs.
3. **DevOps/operations:** CR-01, CR-06. [serve.py:4–7](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/serve.py#L4-L7) describes network binding for a demo. Backups, monitoring, restoration and release controls are unverified; Pages deploys only the visualization.
4. **OWASP/security:** CR-01/03 concern authentication, authorization and learner data. The [threat model:29–44](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/specs/security/threat-model.md#L29-L44) claims injection, SSRF, secret and privacy controls; these are design claims, not validated safeguards. Console accepts a token in a query string ([console.py:102–109](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/app/lib/console.py#L102-L109)), which risks browser/history or intermediary disclosure. Dependency vulnerability status, retention, encryption, CSRF, TLS and actual secret handling are unverified.
5. **UI/UX/accessibility:** CR-04/07 create misleading evidence. The overview labels the presentation as a demo and fixture cohort, which is useful, but its [buttons:201–210](https://github.com/knarayanareddy/Courserefresh/blob/b475254cf7aafa5fb535a9987a48e5379ce57e27/viz/src/App.tsx#L201-L210) have no handlers in the inspected markup. They should be clearly illustrative or functional. Keyboard, focus, screen-reader, contrast and video caption behavior were not tested.

## Production blockers and owner decisions

Before real learners or network exposure, resolve CR-01–03. Owner must select platform, identity, consent, retention, TLS, credentials, service accounts and cost limits; decide whether demo controls are operational; approve release, recovery, incident response and human review. No certification or current production use is claimed.
