# Anatomy of a production agent

**Learning objective.** Map the six loop phases onto concrete components, and trace one real event end-to-end naming the artifact each phase writes.

## 1. From loop to machine

Last lecture the loop was a shape. Today it becomes parts. For each phase: the
component that implements it (in running case study), and the artifact it leaves.
This table is the course in miniature — keep it pinned while you build anything:

| Phase | Component | Artifact written |
|-------|-----------|------------------|
| NOTICE | **Apify actors** on schedules: `website-content-crawler` (pinned build) fetches each source; a **normalize+dedupe** pass hashes content and skips what is unchanged | Hashed snapshot on disk (`snapshots/<source>-<sha>.md`); a `no_delta` row in `run_log.jsonl` for unchanged sources |
| VERIFY | n8n Code nodes in the **triage workflow**: `BUILD_PROMPT`, `ANCHOR_QUOTES` | Anchored verbatim quotes attached to the claim |
| DECIDE | The judge (an LLM answering closed questions — Lecture 14) **feeds** the **POLICY node** (ordered rules in a Code node — Lecture 15) | **A receipt**: full decision input, the action, reason codes, quotes, artifact hashes |
| ACT | The **act workflow**: render, diff, commit to the course branch, notify consented learners | New lesson version `vN.md`, `diffs/vN.diff`, a `CHANGELOG.md` row, a learner card |
| LEARN | The **learn workflow** on a 15-minute schedule: reads telemetry, checks gates, dispatches help | Gate states (`open`/`satisfied`/`unmeasured`), micro-lesson files, dispatch receipts |
| REPORT | The **digest workflow** at a fixed time | `digest.md` (≤ 4 KB, refusals first) + `verify_chain()` run over the receipt log |

The one-line architecture: **actors fetch the world, code judges the evidence by
rule, the policy decides, the system acts in versions, the loop learns, and the
digest testifies.**

## 2. Why this division of labor (and not another)

Three design commitments explain why the parts sit where they sit:

1. **Data acquisition is outsourced and pinned.** Fetching real pages reliably
   (retries, proxies, JS rendering) is a hard, boring job that Apify has already
   industrialised. Pinning the actor *build* makes every fetch reproducible — the
   snapshot you hashed in March is the snapshot you can re-derive.
2. **The decision is code, not vibes.** An LLM *proposes* answers to closed
   questions; a Code node *disposes*. No model call sits inside the decision path.
   This is why the same decision is reproducible, testable in CI, and portable
   between runtimes (Lecture 15’s parity tests).
3. **Every phase leaves an artifact a human can read.** If a phase ran, something
   on disk proves it and names why. A phase that cannot show its artifact is
   redesigned until it can.

## 3. Tracing one event end-to-end

The best way to learn anatomy is one full heartbeat. Here is the real publish
`cr-20260926-1726-793` (receipts in `specs/evidence/`), compressed; we read it in
full in the lab:

```
03:02  NOTICE   wf-cr-0-scan (schedule: every 60 min) runs the pinned actor
                 over 6 sources. GitHub n8n releases page returns new content;
                 hash differs from `seen.json` → event. Other sources: no_delta.
03:02  NOTICE   Normalized: {event_id: cr-n8n-rename-01, claim: "n8n 1.85
                 renames tool_permissions to permissions.mode", sources: 3}.
03:03  VERIFY   Triage webhook receives the scan; BUILD_PROMPT assembles the
                 snapshot excerpts; ANCHOR_QUOTES pins the verbatim sentence
                 from the release page into the claim.
03:03  DECIDE   Judge answers the closed questions: materiality =
                 material_breaking; sources_verified = 2 (vendor voices) —
                 release notes + docs are ONE publisher, the npm package page
                 is the second voice. POLICY: rules R1..R7 don't fire; R8
                 → PUBLISH at authority PA2. Receipt rcpt-26-793-000.
03:05  ACT      Lesson 04 v4 written; diff against v3; quiz item regenerated
                 (the old item tested the old setting name); CHANGELOG row;
                 commit on bot/courserefresh; 7 learner cards staged
                 (consented cohort), 1 learner excluded by design.
03:05  LEARN    Gate armed AT PUBLISH TIME: quiz_delta <= 0 within 48 h with
                 n >= 5 → auto-revert. (Two days later it fired; the receipt
                 rcpt-26-793-008 restored v3. The system undid its own work
                 because it had promised to.)
07:30  REPORT   Digest: 2 publishes, 4 refusals, chain verified. Refusals
                 first. 4 KB, built from receipts only.
```

Notice what the trace demonstrates: the event is *checkable*. "The system renamed a
setting in the lesson" is not a claim you take on faith; it is a commit you can
diff, a receipt you can read, a quote you can compare against the hashed snapshot.

## 4. Component inventory as a design pattern

When you design your capstone system, produce this table for *your* subject before
writing any workflow — it is the design document your reviewers will actually use:

```
subject:        <what moves>
sources:        <authoritative> / <corroborating> (publishers, not URLs)
notice:         <actor + build pin + cadence>
verify:         <what makes a claim supported>
decide:         <your rules, one line each, in order>
act:            <artifact + versioning + who gets notified>
learn:          <what would make the action wrong, measured how>
report:         <who reads the digest, and when>
```

If any row is blank, that row is where your system will fail first.

## 5. Common mistakes

1. **Noticing without hashing** — the scan ran, but you cannot prove what it saw.
   Unverifiable noticing is rumor.
2. **Acting without versioning** — overwriting in place. No diff, no undo, no
   argument. Every write is a new version.
3. **Learning as an afterthought** — a "we'll add analytics later" plan means the
   gate that would have caught a bad publish does not exist when it matters.

## Recap and practice

You can map phases to components and read an end-to-end trace at receipt level.

**Practice:** take the trace in §3 and (a) name the artifact you would fetch to
disprove each step; (b) identify at which phase the npm page mattered to
independence; (c) write down what would have happened had `sources_verified` been
1. *(Escalate — insufficient corroboration — nothing published, claim preserved for
the human.)*
