# Micro-lessons & messaging caps

**Learning objective.** Write a micro-lesson to the fixed three-part contract under the word cap; state the message caps (1/learner/day, 3/learner/week, 1/concept/7 days) and why they live in code, not copy.

## 1. From signal to help

Lecture 19 defined the stuck signals and the wall. This lecture is what a
consented, signalled learner actually receives: **one micro-lesson — two minutes,
one concept, one practice item — sent before they ask.** The entire intervention
is deliberately tiny, because the intervention's job is not to teach the whole
topic; it is to hand the learner the one concept they slipped on, at the moment
they slipped, without making them feel watched, graded, or behind.

## 2. The format contract

The format is fixed by contract, and the contract is *tested* — a malformed
micro-lesson is a build failure, not a style preference:

```
# <concept> — two minutes
1. What it is        (three sentences)
2. One worked example  (≤10 lines, mono, from the lesson's own code)
3. One practice item (multiple choice, answer explained)
[Stop these messages]   [See what changed]
```

Worked example from the running repo (dispatched on the `permissions-mode`
concept after the n8n rename — 220-word cap respected):

```
# permissions-mode — two minutes
1. What it is
The tools an agent may call, and their parameters, are declared under
`permissions.mode` (formerly `tool_permissions`) in the workflow settings.
A model may ask for a tool; the runtime refuses anything outside the declared
scope. If it is not in the settings, it does not exist.
2. Worked example
{ "permissions": { "mode": { "tools": ["http_request"],
    "parameters": { "http_request": { "allow": ["docs.n8n.io"] } } } } }
The allowlist is host-scoped: a redirect to another host is a refusal, not a run.
3. Practice
An agent needs to read docs.n8n.io and nothing else. Smallest correct permission?
   a) all tools, read-write        b) read on docs.n8n.io only
   c) no tools and a retry loop
Answer: b — the scope is declared, host-limited, and nothing else exists.
[Stop these messages]  [See what changed]
```

Contract details that are load-bearing:

- **Names the concept** — the micro-lesson must say exactly which concept it is
  (the stuck signal named one; the help must answer to the same name).
- **Example from the lesson's own code** — help points back at the course, not at
  Wikipedia; the learner re-enters the same artifact they were struggling with.
- **Never graded, never scored, never reported beyond the learner.** The word
  "graded" is contractually banned from the artifact (tested); the practice item
  explains its answer; nothing about the dispatch enters any evaluation of the
  *learner*.
- **The opt-out is in the artifact**, every time — not a setting to hunt for.
  "See what changed" links the concept to the change stream (the learner sees
  *why* the lesson they read may have been confusing: the subject moved).

## 3. The caps — in code, not in copy

Three caps, hard-coded in the policy, checked *before* the dispatch, receipted
when they fire:

| Cap | Value | Fires as |
|-----|-------|----------|
| Per learner per day | 1 micro-lesson | `NO_CHANGE [rate_limited]` + receipt |
| Per learner per week | 3 micro-lessons | `NO_CHANGE [rate_limited]` + receipt |
| Per concept per 7 days | 1 per concept | `NO_CHANGE [rate_limited]` + receipt |

Why "in code, not in copy" deserves its own section: because the caps are the
difference between help and harassment, and **copy-declared limits drift under
product pressure**. "We aim for at most one message a day" becomes "this one is
important" becomes three. The running repo keeps the caps as policy constants —
changing one is a versioned amendment with a receipt trail, not a copy edit. The
cap checks run in the same policy block as everything else (first-rule-first),
and the *refusal to over-message is itself a decision with a receipt* —
`rate_limited` rows prove restraint the same way `consent_missing` rows prove
the wall.

Note the cap-check order in the dispatch decision: consent first (Lecture 19 —
the wall outranks helpfulness), then caps, then signal. A willing learner
dispatched twice in a week for the same concept is *also* a `rate_limited`
refusal — even eagerness doesn't shift the caps.

## 4. The dispatch, receipted

```
LEARN workflow (15-min schedule)
  READ_TELEMETRY → stuck_check → consent_check → cap_check → DISPATCH
                                                       │
   receipt: [stuck_signals_met] · learner:<hash> · concept: permissions-mode
   artifact: micro-lessons/ml-permissions-mode-k-01.md  (screens to the card)
   edits: cap counters incremented · dispatch counters for digest panel
```

The dispatch receipt is deliberately quiet about the learner (hash only, per the
no-names law) and deliberately loud about the *decision*: which signal fired,
which caps were checked and passed, which concept. If a learner later says "why
did I get this message?", the receipt answers with the signal facts — two wrong
answers on this concept, within this session, consent version N — without ever
naming the learner to anyone else.

What the digest reports is aggregates only: `micro-lessons dispatched: 1 ·
blocked for missing consent: 1 · rate-limited: 0 · cohort quiz delta:
unmeasured` — numbers with their refusals, refusals first as always.

## 5. Common mistakes

1. **The mini-lecture.** A 900-word "micro-lesson" is a lesson the learner didn't
   ask for, arriving in a notification channel. The 220-word cap is the
   intervention design: two minutes or it isn't help, it's homework.
2. **Caps in the prompt.** "Try not to send more than one a day" — the model
   *believes* it; the runtime must *enforce* it. Caps are policy constants with
   receipts.
3. **Graded practice.** The moment the practice item's answer feeds any score,
   the micro-lesson has become surveillance with a quiz. The word "graded" is
   banned from the artifact *and* from the telemetry it feeds.
4. **Help without provenance.** A micro-lesson that doesn't name its concept
   (and link the change that likely caused the confusion) is a tip, not a loop
   closing. The [See what changed] link is the learner-side face of the whole
   change-receipt apparatus.

## Recap and practice

You can write a contract-clean micro-lesson and recite the caps with the
in-code-not-in-copy argument.

**Practice:** (a) Write the micro-lesson your capstone would dispatch for its
likeliest stuck-concept — three parts, ≤220 words, concept named, opt-out
present, zero grading vocabulary. (b) Then the adversarial check: your cohort
lead asks for "a friendly reminder" to non-consented learners who look stuck.
Write the two-line refusal — name the reason code the receipt would carry, and
the lecture whose wall you're citing. *(consent_missing; Lecture 19, §2 — the
refusal is itself the artifact.)*
