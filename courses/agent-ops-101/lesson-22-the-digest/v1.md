# The morning digest: the system's face

**Learning objective.** List the five digest sections in fixed order and explain why refusals come first; extract the operational facts from a real digest — mode, measured cadence, budgets, gates, the unmeasured list.

## 1. One page, with coffee

The digest is the *entire* product surface for the person who pays for the
system: every morning at 07:30, one page, ≤ 4,096 bytes, generated **from
receipts only** — never from memory, never from optimism. If a number is in the
digest, a receipt produced it; if no receipt produced it, the number is not in
the digest. The design brief reads like a newspaper: the operator should be able
to read it in two minutes and *know what the system did, what it refused, and
what it could not tell* — the Monday question (Lecture 01) answered by a
document.

## 2. The five sections, in fixed order

```
=== COURSEREFRESH DIGEST ===                                    §0 run header
run_id: cr-20260926-1726-793 · mode: sim · cadence: 63 min (measured)
Apify: 18.4 units · Tokens: 42,100 · Publishes: 2 · Refusals: 3

── REFUSALS (3) ─────────────────────────────────────────────── §1 refusals
[REFUSED] cr-single-01 · insufficient_corroboration
  Quote: "n8n 1.86 removes the HTTP Request node"
  One source (n8n community forum). No corroboration found.
[REFUSED] cr-inject-01 · injection_or_jailbreak
  Hostile instruction detected in scraped page. Event preserved, receipt …
[REFUSED] cr-assess-01 · assessment_integrity
  Change would alter quiz answer key. PA3 — human required.

── CHANGES (2) ──────────────────────────────────────────────── §2 changes
[PUBLISHED] lesson-01 v3→v4 · corroborated_change · PA2 · gate: armed
  n8n 1.85 UI rename …
[PUBLISHED] lesson-03 v4→v5 · threshold_update · PA2 · gate: armed

── LEARNERS ─────────────────────────────────────────────────── §3 learners
Cohort: 12 window · micro-lessons dispatched: 1 · blocked (consent): 1 ·
rate-limited: 0 · quiz_delta: unmeasured (n=2, window elapses 09-28)

── DISCIPLINE ───────────────────────────────────────────────── §4 discipline
chain ✓ 9 rows · receipt coverage 100% · budget 18.4/25 units ·
unmeasured: quiz_delta cohort-01, cost eur · digest 3,412/4,096 bytes
```

**Why refusals first is a safety property, not a style choice:** the operator
with two minutes reads section one. An operator who reads only refusals still
knows whether any safety boundary was approached — the most important fact about
an autonomous night. A digest that leads with successes buries the signal;
refusals-first makes the *first scroll* the audit. (The order is contract-tested:
§1 must exist, must be first, must aggregate by reason code.)

## 3. Reading the header like an operator

The three-line header answers the questions that decide whether to keep reading:

- **mode** — `live / sim / degraded`, the honesty label from Lecture 08. A sim
  digest's numbers are mechanism-proof, not outcome-proof; the label tells you
  which questions are fair.
- **cadence (measured)** — "63 min (measured)" is the *observed* interval with
  jitter, against the configured 60: cadence honesty in one number. A widening
  gap is the earliest symptom of a struggling loop (actor timeouts, retry
  storms — Lectures 06, 09).
- **budgets** — units and tokens spent *against caps*, in header position
  (Lecture 09's meter on the front page). The operator checks spend before
  reading anything the spend produced.

## 4. §4: the discipline strip

The bottom strip is the self-audit, five facts, every morning:

1. **chain ✓ n rows** — verify_chain() ran at run end (Lecture 16). Present and
   true, or the digest itself is suspect.
2. **receipt coverage** — 100% or there is a decision without a receipt and the
   next section owes an explanation.
3. **budget against cap** — the same meter, closing position.
4. **the unmeasured list** — *every* quantity the run could not measure, named:
   `quiz_delta cohort-01`, `cost eur`. Not hidden in a footnote: enumerated. The
   list is the digest's confession posture and its most trustworthy feature — a
   system that never says unmeasured is either omniscient or lying.
5. **digest size** — 3,412/4,096: the document audits its own budget (the byte
   cap is contract-tested; a digest that outgrows its page learns to summarise
   its refusals, which is the wrong lesson — so budgets elsewhere get checked
   first).

## 5. The digest as test oracle

Because the digest is generated-from-receipts-only, it doubles as a consistency
check for the whole system: §1's counts must equal the receipts' escalate rows;
§2's versions must exist on disk with matching diff hashes; §3's dispatches must
match micro-lesson receipts; §4's chain row must be reproducible. The repo's
tests assert these joins — **the digest is the system's story, and the story must
reconcile with the books** (receipts). When they disagree, that is not a digest
bug; that is the incident you were about to miss.

Failure mode worth memorising: the *missing* digest. Since the digest is how
silence is defeated, its own absence must fail loudly — the watchdog route
(Lecture 08, §5). "Digest did not arrive at 07:31" is itself an alert condition;
a system whose failure mode is a quiet morning has smuggled silence back in
through the report layer.

## 6. Common mistakes

1. **The achievements digest.** "We're excited to share three improvements…"
   Marketing-tone digests get skimmed; skimmed digests hide refusals; hidden
   refusals become incidents. Newspaper, not newsletter.
2. **Numbers without receipts.** Any figure the receipts cannot produce is a
   fabricated number wearing a uniform. Generated-from-receipts-only, enforced
   by tests, no exceptions for "obviously true" values.
3. **Unmeasured quietly omitted.** The empty `unmeasured:` list nobody notices
   missing. Print the list with its n's even when — *especially* when — it's
   embarrassing.
4. **Configurable section order.** "Teams can reorder sections to taste" —
   refusals-first is a safety property; making it a preference makes safety a
   preference. The order is fixed by contract, and the contract is tested.

## Recap and practice

You can recite the five sections with the refusals-first argument, read a header
(mode/cadence/budget), and audit a discipline strip.

**Practice:** (a) Here is the morning after YOUR capstone's first overnight run
in sim mode: 1 publish, 1 hostile-refusal, 1 unmeasured gate, budget 61% used.
Write the digest — all five sections, honestly sized, refusals first. (b) Then
the adversarial read: which single line would a judge point at to test whether
your system is honest? *(The unmeasured list — anyone can print successes;
systems that print their ignorance are rare and serious.)* (c) And the
operational question: your 24-hour digest shows measured cadence 127 min against
configured 60 — no refusals, no errors. What's your first diagnostic move?
*(Actor run times and retry storms at the notice layer — Lectures 09/11: check
fetch duration distribution before touching the decision layer.)*
