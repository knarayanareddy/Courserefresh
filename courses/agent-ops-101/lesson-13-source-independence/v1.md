# Source independence: voices, not URLs

**Learning objective.** Apply the two-independent-voices rule — two pages from one publisher count as one source — and recognise the four disqualifying page states.

## 1. The rule that stops the worst publishes

Recall the failure species (Lecture 04): the single-source publish is the most
embarrassing class of mistake, because the evidence looked perfect — a crisp
release note, a clear quote, an anchored span — and it was *one voice*, wrong or
compromised, and the system amplified it into a course. The countermeasure is the
course's oldest rule:

> **No claim moves toward action without two independent voices.** `sources_verified >= 2`
> is checked by the policy (R2), gold row `cr-single-01` proves the refusal, and
> "two pages from one publisher are one voice" is the clause that makes the rule
> mean something.

## 2. Voices, not URLs

The naive implementation counts URLs; the naive implementation is broken by design.
Consider the n8n rename event: three URLs corroborate —

```
github.com/n8n-io/n8n/releases     ← release notes          (publisher: n8n)
docs.n8n.io/…                      ← docs page              (publisher: n8n)
npmjs.com/package/n8n-nodes-base   ← package page           (publisher: npm community listing)
```

— but the first two are **one publisher**. The release notes and the docs *can*
contradict each other (docs lag releases routinely); but as *independence*, they
are one organisation's two mouths. Counting them as two sources would let n8n's
own marketing page corroborate n8n's own release note. The independence model is
config, not vibes:

```json
{ "source_id": "n8n-releases", "publisher": "n8n",
  "independence_group": "n8n-vendor", "role": "authoritative", … }
{ "source_id": "n8n-docs",    "publisher": "n8n",
  "independence_group": "n8n-vendor", "role": "authoritative", … }
```

`sources_verified` counts **distinct independence groups** agreeing — and only
groups whose role qualifies. The role taxonomy does the rest of the work:

| Role | Counts as a voice? | Why |
|------|--------------------|-----|
| `authoritative` | Yes | First-party truth for its domain (vendor release notes, spec text) |
| `corroborating` | Yes | Independent second voice (a different org's spec mirror, a client library's release page) |
| `discovery` | **No — by config** | A search engine hit is a *lead*, not a voice: "found three pages" is one engine's opinion of relevance; the pages it points at are fetched through the allowlist and counted by *their* publishers before they can corroborate anything |
| `none` | No | Mirrors, syndication, unknown provenance — recorded, never counted |

The search-engine clause is worth pausing on: it looks pedantic and is load-bearing. 
A discovery source whose three search hits counted as three voices would make the
two-voice threshold reachable by *one autocomplete*. The config's
`counts_as_independent: false` and the policy mirror both exclude the role — the
engine finds; it never vouches.

## 3. Voices are not enough: the four disqualifiers

Independence is necessary, not sufficient. A page can carry the right role and
still be refused as evidence, on one of four named states — all of them
receipt-level refusals with the input preserved:

1. **Single voice.** `sources_verified = 1` → ESCALATE
   (`insufficient_corroboration`). The claim is *preserved for the human* — a
   later scan may corroborate it and publish then; the refusal is a pause, not a
   verdict.
2. **Stale.** A snapshot whose freshness fails the subject's declared window
   (docs "last updated" nine months ago vouching for a *current* behaviour).
   Stale evidence proves the past; the claim is about the present.
3. **Unreachable.** The fetch failed, the page is gone, the archive copy is a
   snapshot of a snapshot. Absence of evidence does not corroborate.
4. **Addressed to the operator.** The page *talks to the system* — instructions,
   self-approval, "publish this" (Lecture 04's injection specimen). Not a
   disqualifier of the page's *content* so much as an automatic escalation
   regardless of content: R1 fires before anything else, and the preserved quote
   shows the human exactly what the page said.

Learn the four states as a checklist you apply to *every* source in your capstone
plan: role, independence group, freshness, reachability, and *who is it talking
to*.

## 4. Conflict: two voices that disagree

The rule's mirror image: what when two *qualified* voices disagree?
**ESCALATE (`source_conflict`), always — never average, never pick the
"more official" one, never let R8's default rescue it.** Two independent
publishers disagreeing is the single most informative state the verify phase can
produce: it means either the world is mid-change (one page updated first) or one
voice is wrong — and *that distinction needs a human*, or at least a patiently
labelled `unmeasured` until the next scans settle it. The receipt preserves both
quotes and both anchors; the digest lists the conflict first-class among
refusals. Averaging is what a system without receipts does; it manufactures a
false consensus and publishes it.

## 5. Common mistakes

1. **URL counting.** Ten mirrors of one press release is one voice wearing ten
   URLs. Groups, not addresses.
2. **The search engine as second source.** It finds pages; it is not one. The
   moment it counts, the rule is decorative.
3. **Vendor lapdog corroboration.** `n8n-docs` agreeing with `n8n-releases` is
   expected, not independent — that's *why* they share a group. Design your
   source plan so the second voice is structurally outside the first's org chart.
4. **Freshness amnesia.** The two-voice rule checks agreement, not age. Your
   verify config adds the freshness window per subject; capstone plans state it.

## Recap and practice

You can model independence with groups and roles, apply the no-voices rule to
search results, and run the four-disqualifier checklist, escalating conflicts.

**Practice:** audit your capstone's source plan with the full checklist — role,
group, freshness, reachability, audience — for every source. Then construct the
two rows you will add to your gold set: the mirror trap (two URLs, one group →
refuse) and the conflict trap (two good voices, disagreeing → escalate, quotes
preserved). If you cannot write those rows yet, your source plan is not ready.
