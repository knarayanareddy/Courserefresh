# The autonomy ladder: from chatbot to autonomous system

**Learning objective.** Place any system on the autonomy ladder, explain why authority is earned and reversible, and read a concrete authority ladder (PA0–PA3) well enough to predict what is permitted at each rung.

## 1. The ladder

Autonomy is not a switch; it is a ladder, and each rung adds a class of behaviour
the system may perform *without asking*:

| Rung | Initiates | Decides | Acts | Example |
|------|-----------|---------|------|---------|
| 0 — **Tool** | Human | Human | System (mechanically) | A calculator; a cron job |
| 1 — **Chatbot** | Human | System (suggests only) | Nobody | Q&A support bot |
| 2 — **Copilot** | Human | System (suggests) | Human | Code autocomplete; "apply fix?" dialogs |
| 3 — **Supervised agent** | System | System | System, **with receipts and undo** | Courserefresh |
| 4 — **Autonomous agent** | System | System | System, no per-action human review | (We never ship rung 4 in this course) |

The engineering question is never "is it an agent?" but "**how far up the ladder
does a specific behaviour sit, and what evidence earned it that rung?**" A mature
system has different behaviours at different rungs simultaneously: Courserefresh
auto-publishes lesson text at one rung but will never touch a quiz answer key at
any rung — that action is pinned to the human-only tier forever, no matter how well
the system behaves.

## 2. Earned, not declared

Here is the principle that separates production agent systems from toy demos:

> **Authority is earned by evidence and revoked by rule — never declared in a
> prompt, never granted by default.**

Why *earned*? Because the cost of an agent's mistake is not symmetric with the
benefit of its work. A system that publishes 100 good updates and one catastrophic
one has not "averaged out"; it has destroyed trust. So authority starts at zero and
is granted in exchange for a track record you can point at: N consecutive clean
actions, zero rollbacks, gates armed and honoured.

Why *revocable by rule*? Because earned authority that cannot be lost is not earned.
The revocation must be mechanical — a rule fires, the ladder descends — not a matter
of somebody noticing "it's acting weird" (they won't; nobody is watching, that was
the point).

A prompt is not a permission system. Writing "you are allowed to publish lessons"
into a system prompt gives the model a *belief*, not a *capability*. Real authority
lives in the runtime — the workflow settings, the branch permissions, the token
scopes — and the lecture-long version of this is Lecture 17.

## 3. The PA0–PA3 ladder (the concrete version)

Courserefresh ships this ladder in its workflow settings, and the policy node
enforces it on every decision. Learn to read it fluently — you will implement one
in the capstone:

```
PA0 — Observe only.    Drafts changes, publishes nothing, notifies nobody.
                        Default state on first run. Earned automatically? No —
                        it is the starting point; nothing is earned yet.

PA1 — Act quietly.     Publish versioned lesson edits to the course tree.
                        No messages to learners.
                        Earned by: first clean preflight (consent, budget,
                        chain integrity all green).

PA2 — Act and notify.  Publish + send a card to consented learners affected
                        by the change.
                        Earned by: 3 consecutive accepted publishes, 0 rollbacks.
                        Lost by: any rollback — one bad publish resets to PA1.

PA3 — Human only.      Assessment changes (quiz answer keys, grading), learner
                        records, anything irreversible (deletes, payments,
                        outbound mail to non-consenting recipients).
                        Never earned. Never delegated. No exceptions "for the
                        demo".
```

Two properties to notice. **Monotonicity within a class:** a system at PA2 may do
everything PA1 may do. **A ceiling that never moves:** some actions sit above the
ladder entirely — no rung unlocks them, which is what "PA3 forever" means.

**Reading a ladder is a skill.** Given "the system is at PA1 and a corroborated,
material breaking change arrives," you should say instantly: *publishes the lesson,
sends no cards*. Given "the same change touches a quiz answer key": *escalates to a
human regardless of corroboration*. We drill this in the practice below and it
becomes second nature by Lecture 15.

## 4. The ladder is a *per-action* property, not a per-system badge

Subtle point worth a paragraph: when we say "Courserefresh is at PA2," that is
shorthand. The precise statement is: *for the action class "publish lesson text,"
the system currently holds PA2*. The same system holds PA0 for action class
"assessment change" and always will. Debugging an autonomy failure usually means
discovering that somebody treated a system-wide badge as a blanket permission.

The mechanism that keeps this honest is boring and absolute: the **policy node**
checks the action's class *and* the current authority level *and* the rule
history, on every single decision, and refuses anything the intersection does not
allow. There is no code path that skips the check.

## 5. Common mistakes

1. **"It earned PA2 next week's demo."** Authority is earned by *recorded* evidence
   (receipts), not by schedule pressure. If the record shows 2 clean publishes, it
   is 2, and the ladder says no.
2. **Silent ladder-climbing.** If the level changes, the digest must say so, with
   the receipt ids that earned it. A level change nobody can see is a defect.
3. **Granting the ladder in the prompt.** "You are a PA2 agent" in a prompt is a
   costume. The model can believe it; the runtime must still refuse.

## Recap and practice

You can place systems on the ladder, explain earned-and-revocable authority, and
read PA0–PA3 fluently enough to predict permitted actions.

**Practice (do all three):**
1. Courserefresh sits at PA2. A corroborated rename inside lesson text arrives.
   Predict the behaviour. *(Publish + notify consented learners — PA2 permits it,
   the evidence satisfies the rules.)*
2. Same system, same evidence — but the change rewrites a quiz's correct answer.
   *(PA3: escalate to a human, publish nothing, preserve the evidence quote.)*
3. A rollback gate fires overnight. Where is the system on Monday? *(PA1 — a
   rollback resets the consecutive-accepted counter; the digest names the reset
   and the receipts that caused it.)*
