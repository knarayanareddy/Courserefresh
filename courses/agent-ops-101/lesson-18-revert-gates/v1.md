# Revert gates: publishing means promising to undo

**Learning objective.** Write a revert gate at publish time — metric, threshold, cohort minimum, deadline — and distinguish open, satisfied and unmeasured gates and what each obliges the system to report.

## 1. Falsification, borrowed from science

A course update is a hypothesis: "this new version is better than the old one."
Science's hardest-won habit is that hypotheses must be **falsifiable** — the
experimenter writes down, *in advance and in public*, the observation that would
prove the hypothesis wrong. Courserefresh imports the habit wholesale: at publish
time, the system writes a **gate** — the pre-registered condition under which it
will undo its own work:

```json
{ "metric": "quiz_delta",   "condition": "<= 0",
  "n_min": 5,               "window_h": 48 }
```

- **metric** — what gets measured after learners interact (`quiz_delta`, or for
  other subjects `completion_delta`, `stuck_rate_delta`)
- **condition** — the value at/below which the gate *fires* (quiz scores did not
  improve: the change is presumed harmful or useless)
- **n_min** — the cohort floor: measurements below it cannot act (small-n
  arithmetic is noise; Lecture 21 generalises the discipline)
- **window_h** — the evaluation deadline: gates are time-boxed, not eternal

The gate is recorded **inside the publish receipt's inputs** (Lecture 16's §) —
written *before* any learner touches the new version, immune to post-hoc
rationalisation. A gate written after the data arrives is not a gate; it's a
press release.

> **Publishing means promising to undo.** The promise is the artifact that makes
> an autonomous edit ethical: the system grants the world the right to prove it
> wrong, and binds itself to obey.

## 2. The three states

Every gate is, at any moment, in exactly one of three states — and the digest
reports each differently because each obliges something different:

| State | Meaning | System obligation |
|-------|---------|-------------------|
| **open** | Window running; not enough data yet | Report it exists, with deadline. No action, no claims |
| **satisfied** | Metric crossed the condition **with n ≥ n_min** inside the window | **Auto-revert** — restore the prior version as a *new version*, receipt `revert_gate_satisfied`, notify the same cohort that received the publish. No human in the loop: the promise executes |
| **unmeasured** | Window elapsed with n < n_min (or telemetry lost) | Report `unmeasured` with n and the values seen. **No revert claim, no harm claim.** The honest sentence: "we could not tell whether the change helped" |

The `unmeasured` state is the one that separates operated systems from marketing
systems: it is *always available*, always tempting to skip, and always reported.
"Quiz delta +12% (n=3)" is a number pretending to be evidence; n=3 is a report,
not an action. The system never conflates the two — a claim without its n is a
hype violation (Lecture 21's claims lint makes the same rule syntactic).

## 3. What a revert actually is (and is not)

A revert is **not an undo**. It is a **new version whose content restores the
prior one**, with everything a publish has:

```
lesson-04/
  v3.md          original
  v4.md          the publish (2026-04-18, gate: quiz_delta <= 0, n>=5, 48h)
  v5.md          the REVERT of v4 (2026-04-20, receipt rcpt-26-793-008)
  diffs/v4.diff  (+) and (-) of the publish
  diffs/v5.diff  the revert's own diff
  CHANGELOG.md   both rows, both receipts
```

Why a new version rather than an undo? Because **the revert must itself be
arguable**: it gets a receipt (satisfying the *recorded* gate — the receipt
quotes the gate *as written at publish time*), a diff (restoring v3's text is
itself a change to the current), and a notification to the same cohort ("the
change you were told about has been undone, here is why"). History never
rewrites; it appends the correction. (This is Lecture 16's chain discipline
applied to the system's own mistakes.)

And the discipline cuts both ways — **a revert on vibes is forbidden**. An author
feeling the change "seems wrong" does not fire the gate; the metric does, with n.
The human override exists but is *honest about being human*: override receipts
say `decided_by: human:<name>` (and the tasteful version adds a reason in prose).
Machine promises revert by rule; humans revert by authority and say so.

## 4. The lifecycle, end to end

```
publish v4 ──▶ gate armed (in receipt) ──▶ LEARN workflow evaluates every 15 min
                │                              │
                │                         n < 5 by 48h ──▶ digest: "UNMEASURED (n=3,
                │                              │            required 5, window elapsed)"
                │                         quiz_delta <= 0 at n >= 5
                │                              │
                ▼                              ▼
        cohort notified of v4        REVERT: v5 = content of v3 · receipt
                                       · notify cohort · ladder resets to PA1
```

Two production details from the trace: the **ladder resets on revert** (Lecture
02's earned-authority rule: one bad publish un-earns notify privileges until
three clean publishes re-earn them), and the **same cohort** is notified — a
learner told "lesson 4 changed" who is never told "it changed back" has been
abandoned in a version that no longer exists.

## 4b. Reverts earned, not begged

The trace above is real: the running case study published v4 on corroborated
evidence (receipt rcpt-26-793-000), armed the gate, and two days later the gate
fired — `quiz_delta −0.04 at n=6 after 60h` — and restore v3 *unprompted*
(receipt rcpt-26-793-008). Nobody noticed the mistake first; the promise did.
When judges ask "what happens when it's wrong?", the answer is this receipt —
not a promise to be careful.

## 5. Common mistakes

1. **The unmeasured dodge.** Reporting "gate did not fire" without the n —
   smuggling a satisfied-looking report out of an n=2 window. Unmeasured is
   printed with its n, every time, or the system is claiming what it cannot
   know.
2. **Gates as decoration.** Arming gates that nobody evaluates (no LEARN pass,
   no digest line) — the promise exists but never executes; a gate unwired to
   its evaluator is a lie with JSON formatting.
3. **Revert-as-undo.** Deleting v4 and renaming v5→v4 breaks the chain, the
   diffs, and the trust. Append corrections; never rewrite history.
4. **The vibes revert.** An author's discomfort is an escalation, not a revert
   trigger. Rules revert; humans override and *say so*.
5. **One gate to rule all publishes.** Gates are per-publish: each publish
   carries its own pre-registered condition. Reusing last night's gate for this
   morning's publish is measuring the wrong thing confidently.

## Recap and practice

You can write the four-field gate, recite the three states with their
obligations, and explain why the revert is a versioned, receipted append.

**Practice:** (a) Write the gate for your capstone's first publish, then answer
the adversarial question: what would a hostile reviewer say is wrong with
`n_min: 2, window_h: 4`? *(n=2 acts on noise; a 4-hour window on a subject whose
learners study weekly measures nothing — say so before they do: your honest
print is unmeasured.)* (b) Your gate fires while the system sits at PA2. Walk the
full consequence chain — reverting, receipting, notifying, ladder — and *name the
authority level at which the revert executes* (it is not PA2; think about who
promised).
