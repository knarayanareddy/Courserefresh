# Capstone: run the loop on your own subject

**Learning objective.** Choose a moving subject against the two-voices rule, assemble the full loop, and name the artifact each phase leaves — plus the honest-degrade plan for when the canvas, the actor, or the judge is down.

## 1. The whole course, one move

Twenty-three lectures built the disciplines one at a time. The capstone assembles
them into a running system on a subject *you* choose, and the grading contract
(`FINAL-PROJECT.md`) grades the *honesty of the artifacts*, not the enthusiasm of
the demo. This lecture is the assembly walkthrough — the order of operations that
survives contact with a weekend of building.

## 2. Choose the subject (the choice is graded)

The subject decides which disciplines get exercised. Apply three filters, in
order:

1. **Does it move?** A subject whose sources never change during your project
   window gives your loop nothing to notice — a statue for a watchdog. Good:
   fast-shipping OSS tools, protocol specs, regulatory trackers.
2. **Two voices, structurally?** You need an authoritative first party *and* a
   second voice outside the first's org chart (Lecture 13). n8n has its releases
   + the npm package page; a language ecosystem has its spec + implementer
   release logs. If every source you can name shares one publisher, the subject
   fails the second filter — and so does any plan whose "independent" sources are
   mirrors.
3. **Public and fetchable?** Login-walls, hostile anti-bot patterns, or paywalled
   archives drain your actor budget on plumbing instead of evidence. Pin an
   actor, test one source end to end *before* committing the subject.

The pre-registration habit from the sciences (and the running repo): **write the
source plan before building, and publish it.** Your capstone's `SOURCE-PLAN.md`
names each source, publisher, independence group, role, cadence, and the pair of
URLs that *look* independent but aren't — the last item because your mirror trap
(Lecture 21's practice) comes from it.

## 3. Assemble in this order (it matters)

The order below is earned failure-order: each step's artifacts make the next
step debuggable.

```
Week 1 — NOTICE + VERIFY (Modules II–III applied):
  · source plan → config (publishers, groups, roles, allowlist hosts)
  · pinned actor per source · fetch→hash→cache (L12) · dedupe seen.json (L06)
  · required-fields check → parse_failed receipts (L08/L10)
  · deliverable: a scan that runs hourly and leaves no_delta rows for a quiet
    world — the loop's heartbeat visible in run_log.jsonl

Week 2 — DECIDE:
  · seven closed questions for YOUR subject (L14) — contamination-audited
  · policy rules, ordered, closed-taxonomy reasons (L07/L15) — both runtimes
  · gold rows: your eight traps, labelled before any run (L21)
  · parity test green at action match 1.000 before the first real decision

Week 3 — ACT + LEARN:
  · versioned artifact writes with diffs (L16) · notification path with the
    consent wall (L19) · gates armed inside publish receipts (L18)

Week 4 — REPORT + EVAL + DEGRADE:
  · digest, five sections, refusals first, from receipts only (L22)
  · three-column eval on your frozen gold set (L21) · budget caps with
    escalation (L23)
  · chaos drills: break the actor, the judge, the write — read the digest the
    next morning; every failure must be a line, not a silence (L08)
```

The one-line completion criterion (it is the grading rubric in disguise): **every
phase leaves a named artifact, every artifact is checkable by hash, every refusal
is receipted, and every number is either measured-with-n or unmeasured.**

## 5. The seven questions your demo will get

Prepare these answers as artifact pointers, not sentences (the "say this" column
is pointers — JUDGING-MAP style):

1. **"Isn't this an LLM rewriting a doc?"** → seven closed questions + parity
   report. (L14/L15)
2. **"What if the source is wrong?"** → mirror-trap gold row + R2 + gate
   receipts. (L13/L15/L18)
3. **"Who approves this?"** → authority ladder + PA3 wall + signoff receipts.
   (L02/L17)
4. **"What did it do last night?"** → the digest, refusals first. (L22)
5. **"When does it stop?"** → the stop-condition list + the two zero-metrics.
   (L04/L21)
6. **"How do you know it works?"** → three columns, same models, gold frozen.
   (L21)
7. **"What happens when it's wrong?"** → the revert receipt — or the honest
   `unmeasured` + the rule that will fire. (L18)

If an answer needs an adjective, it needs an artifact instead. "Seamless" dies in
demo; a receipt chain survives the follow-ups.

## 6. The honest-degrade plan (the graded safety net)

For each dependency, write the labelled fallback *before* you need it (the
drills in Week 4 exercise each):

| Dependency down | Your labelled fallback | The label the system prints |
|-----------------|------------------------|------------------------------|
| n8n canvas | offline twin decides, same rules (parity earns this) | `OFFLINE TWIN` |
| Apify / actor | fixture snapshots with hashes; live flags off | `DEGRADED` |
| Judge endpoint | fail-closed: escalate `unknown_state`; nothing publishes on judge absence — **never a fallback prompt** | `DEGRADED` |
| Git/repo write | error receipt + preserved diff; retry next cycle | `DEGRADED` (write_failed) |
| Budget | R5 escalation with numbers, coverage named | digest line |

The judge-down row is the one teams get wrong: the temptation is a "backup
smaller model" — but a fallback judge with different calibration turns your
thresholds into folklore (L14's instrument argument). Fail closed instead; the
world survives an hour of no publishes, it does not survive silently miscalibrated
ones.

**And the last discipline: run it while nobody watches.** The capstone's final
week is three overnights with the loop live and no human touch. Friday-you sets
up; Tuesday-you reads digests and argues with receipts. That gap — the loop
running unsupervised and the account surviving scrutiny — is the entire distance
between an agent demo and agent operations. It is the course's whole point.

## Recap and practice

You can choose a subject against the filters, order the build by failure-order,
ship the cupboard, and answer the seven questions with artifacts.

**Practice (the only one — do it): begin.** Write `SOURCE-PLAN.md` tonight: the
subject, the sources with publishers/groups/roles, the mirror pair, the cadence
arithmetic with its declared approximation, and your three chaos drills. Then
build Week 1 — and stop when the world's first `no_delta` row lands in your log.
That quiet, receipted, boring row is the sound of the loop working.
